# 权威链与语义碰撞对抗审计
- 文档 ID：`AUD-061`
- 版本：`1.0.0`
- 状态：`PASS_WITH_EXTERNAL_GATES`
- 审计基线：`ARCH-PCBA-VISION-001 v0.5.3` + `Asun Vision Development Standard v2.1.5`
- 范围：除硬件具体 SDK 外的全量开发准备文档、开发步骤、FunctionSpec、PageContract、工具、权威绑定和语义链路

## 1. 核心问题

故意寻找“一件事情在两个地方都有解释”的情况，并区分**权威定义、投影、解释性视图、实现引用、历史证据**。

## 2. 强制检查对象

`BoardModel` / `ManufacturingGeometrySnapshot` / `InspectionProgram` / `Recipe` / `EffectiveRuntimeManifest` / `BoardRun` / `MeasurementSet` / `InspectionFact` / `InspectionDecision` / `MachineDecision` / `ReviewDecision` / `RouteAssessment` / `FinalDisposition` / `RouteAuthorization` / `BoardExitAck` / `MeasurementQuality` / `MetrologyCapability`。

## 3. 负面场景

- 两个 Owner：必须阻断；
- 两个 Producer：必须阻断；
- 一个 Schema 两个入口：必须阻断；
- 一个 Fact 两个 CommitOwner：必须阻断；
- UI 成为事实写入者：必须阻断；
- Quality Hub 变成第二 Decisioning：必须阻断；
- `DecisionFlowScope` 演变成第二 Authority Registry：必须阻断；
- `CoverageResult` 获得放行权：必须阻断；
- `EffectiveRuntimeManifest` 被当成永久资格证明：必须阻断；
- `ProductionAccepted` 被解释为所有软件状态的线性状态：必须阻断。

## 4. 审计原则

只允许引用已存在的 Contract/Schema/State/Owner；新增语义必须进入 ContractCandidate 并经过真实消费者、Validator、Test、Qualification 的成熟度提升。
